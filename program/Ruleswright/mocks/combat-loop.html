The combat loop

Stepwise and resumable. The engine never demands a whole round in one call — your host animates, prompts, or pauses between any two steps, and snapshots freeze the fight mid-swing.

Turn lifecycle

1 · beginTurn

initiative order · slots granted from pack action economy

→
2 · declare

host picks an action the pack allows · validity checked

→
3 · resolve

effect DSL runs · rolls · saves · damage · conditions

→
4 · endTurn

durations tick · next combatant — or next round

Between any two steps the host may animate, prompt a player, or call serialize(). The engine's only resolution primitive: d20 + attackBonus ≥ defenseTarget — both sides computed by pack formulas (FR-3).

The action economy is pack data

The engine implements a generic slot/points economy — it has never heard of "standard" or "move." The classic turn structure is sample-pack content, and triggered actions ride the event substrate (FR-4, FR-13).

sample pack — action economy
"turnSlots": { "main": 1, "move": 1 },            // classic structure, as data
"actions": {
  "strike":   { "cost": {"main": 1},  "effect": "…" },
  "withdraw": { "cost": {"move": 1},  "effect": "…" },
  "parry":  { "trigger": "event:attacked", "effect": "…" }  // reactive
}

Every mutation carries its why

Provenance is not a log bolted on afterward — it is the payload. UIs, replays, and the triggered-action substrate all read the same stream (FR-13).

event anatomy
{
  "type": "damage:applied",   "at": {"round": 1, "turn": 3},
  "actor": "barrow-wight",    "target": "brynn",
  "payload": { "amount": 6, "hp": "10→4" },
  "why": { "rule": "bestiary.barrow-wight.claw",
           "rolls": ["d20[14]+3=17 ≥ ac15", "d6[4]+2=6"] }
}
combat:startinitiative: wight 17 · brynn 12why: d20[17] vs d20[12] + dex
attack:rolledclaw 17 ≥ ac 15 → hitwhy: claw.attackBonus (pack formula)
damage:applied6 slashing · brynn.hp 10→4why: claw.onHit · d6[4]+2
condition:appliedshaken (1 round) → brynnwhy: wight.frightful-presence
trigger:firedbrynn.parry offered (event:attacked)why: reactive feat · FR-12 proof 2

Hosts may subscribe; the engine never requires one. No subscriber — the game still runs (FR-13).

Snapshots — freeze mid-swing

combat snapshot — state + rng + pack identity
{
  "party": { "pairsWith": "party-1" },
  "round": 2, "turn": 3,
  "order": ["wight","brynn"],
  "rng": { "state": "0x9f3a…" },
  "pack": { "id": "dark-fantasy",
            "schemaVersion": 1,
            "contentHash": "e41c…" }
}
✓

Resume a snapshot and the next roll equals the uninterrupted fight's next roll — testable, not aspirational (FR-14).

✕

Pack hash mismatch on load ⇒ loud refusal, never mangled characters. No v1 migration — the API says plainly that the snapshot is stale.

◈

The engine performs no I/O. Three independent serializers — character, party, combat; a combat snapshot names its party pairing in the docs.
