Stats & abilities — name-keyed

The engine stores abilities and saves by string name. The pack declares which exist; the v1 validator enforces the classic six abilities and the five named saves as a convention (FR-5). Extending either later is a validator relaxation — never an engine change.

pack.stats — the naming contract

pack.json · stats section
"stats": {
  "abilities": ["might","grace","vigor","reason","insight","presence"],
  "saves":     ["vigor","grace","tenacity","reason","presence"]
}

A classic-CRPG pack ships five named saves; a three-save pack ships three; the engine has no opinion. All names coined (Q7/Q8).

Derived stats are pack formulas

HP, AC, attack bonus, save targets, pool capacities — all computed by the formula DSL from abilities, class, level, and equipment. Nothing derived is hard-coded (FR-3).

formula grammar (informal)
term    ::= dice | ability | level
          | class.level | equip.ref
          | number
formula ::= term ((+ - *) term)+
          | min(f, f) | max(f, f)
dice    ::= dS | NdS (kh K | kl K)?
pack.json · formulas section
"hp":          "hd(class) + vigor",
"ac":          "10 + grace + armor",
"attackBonus": "table(class.attack, level) + might",
"saveTarget":  "10 + save.class(save, level)",
"poolCap":     "8 + vigor"

A character is plain JSON

No class instances, no closures, no hidden state — JSON in, JSON out (FR-5, FR-14). Snapshot-safe by construction.

Illegal builds are rejected, rule named

ERROR characters[brynn].feats rule: E-BUILD-01

Feat "twin-strike" requires warden 2+; brynn is warden 1.

hint — legal at warden 2, or choose from: steady-hands, woodwise

ERROR characters[brynn].classes rule: E-BUILD-02

Race hillfolk × class gravehand is forbidden by the race/class restriction matrix (FR-6) — which is pack data, so a permissive pack may allow it.
