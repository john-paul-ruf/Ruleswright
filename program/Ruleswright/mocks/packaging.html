Packaging & surfaces

Three public surfaces, separately consumable (FR-22). The mechanism — subpath exports vs. workspace packages — is an architecture-phase decision; what is fixed here is that runtime-only consumption is first-class and the bundle never carries what you didn't ask for.

The three surfaces

ruleswright/runtime

Dice, characters, parties, combat, conditions, snapshots, events, tables, encounters.

imports generator code: never

ruleswright/schema

The pack format: types, validators, schemaVersion contract (FR-23). Consumed by authors and by the compiler itself.

dependency of both others

ruleswright/compiler

generateCampaign, theme templates, knobs, stage pipeline. Dev-time and host-app territory.

imports: schema + runtime validator

The runtime-only bundle is a proof, not a promise

CI bundle check
entry: "ruleswright/runtime"   // tree-shaken browser build
✓ contains: dice · characters · combat · events · snapshots · tables
✓ absent:   generateCampaign · theme templates · stage pipeline
✓ CI fails if the string "generateCampaign" appears in the bundle

A dev embedding combat in an existing game ships none of the compiler. That is the FR-22 requirement, made enforceable.

The DX contract

✓ Full TypeScript types on every public surface; consumable from plain JavaScript with types available (NFR-DX, NFR-Platform).

✓ ESM primary; Node LTS, evergreen browsers, Electron. No network calls, no telemetry — anywhere.

✓ Near-zero runtime dependencies — build/dev tooling unconstrained, runtime constrained (NFR-Dependencies).

✓ Docs whose examples run — the quickstart mock is the bar: copy-paste, expected output, every step.

One versioning discipline

▲

Packs, overrides, and snapshots share the schemaVersion contract (FR-23): every pack declares it; the engine validates compatibility at load; major bumps are breaking by definition and ship with a written compatibility note. One discipline, learned once — the same contract the snapshot refusal enforces (FR-14).
