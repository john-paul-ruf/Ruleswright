Validation errors

Bad content is rejected loudly at load — errors never surface mid-combat. Every error names three things (FR-2): the artifact's id, the JSON path, and the violated rule. The compiler dogfoods this validator on its own output (FR-17).

One card, four parts

ERROR bestiary[12].actions.claw rule: E-REF-01

Broken reference: action "claw" targets condition "shaken", which does not exist in this pack.

hint — nearest ids: "shaken-1round", "sapped"

Severity stripe · located artifact · stated rule · a hint. The hint is not decoration — it is what makes a 1,200-artifact pack debuggable.

The three rules of failing

All at once. Validation collects every error and reports the full list — fix ten things in one pass, not ten load cycles.

Never partial. A pack that fails any check is never partially loaded. There is no half-alive runtime state.

No eval, ever. Formulas are pure data (NFR-Security) — a bad formula is a validation error, not an execution risk.
