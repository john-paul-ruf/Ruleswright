The optional spatial layer

Packs may declare positions, adjacency, reach, movement, and terrain — on a square grid or a hex grid — or declare none, and everything else works untouched. Theater-of-mind packs pay nothing; tactical packs get geometry (FR-11).

An opt-in, declared per pack

✓ Declared: melee actions may require adjacency; a reach value extends it; burst shapes exist; move actions walk the grid; terrain kinds cost extra or block. All read from the pack.

— Absent: no position state, no adjacency checks, valid clauses never reference distance. A move action resolves as a no-op success (to ignored, nothing emitted beyond action:resolved), and move content still loads; terrain, like positions, rides along unconsulted. Nothing else changes — same combat loop, same events.

pack.json · spatial declaration (v1.5: hex model, terrain vocabulary)
"spatial": {
  "model": "hex",                 // or "grid" (square) — or omit the block
  "reach": { "default": 1, "weapons.long-spear": 2 },
  "shapes": ["single", "burst"],
  "terrain": { "bramble": { "cost": 2 }, "standing-stone": { "blocks": true } }
}

grid is the square grid: Chebyshev distance, 8 neighbors, a diagonal step costs 1. hex reuses the same {x, y} positions as axial {q, r}: distance is (|dq| + |dr| + |dq + dr|) / 2, with 6 neighbors in the fixed order (+1,0) (+1,−1) (0,−1) (−1,0) (−1,+1) (0,+1). Reach, adjacent and burst all use the pack's distance.

Adjacency lives in the action's validity clause

The same action body that works in a spatial pack fails declaratively — never by engine special case — in one that has no geometry.

actions.strike — spatial pack vs. theater-of-mind pack
// spatial pack (dark fantasy)
{ "id": "strike",
  "valid": "hasTarget(adjacent)",
  "cost": { "slots": { "main": 1 } },
  "effect": { "attack": "melee", "onHit": "damage(1d8 + might)" } }

// theater-of-mind pack (same fight, no grid)
{ "id": "strike",
  "valid": "hasTarget(engaged)",   // pack-declared predicate
  "cost": { "slots": { "main": 1 } },
  "effect": { "attack": "melee", "onHit": "damage(1d8 + might)" } }

Area effects resolve through targeting, not geometry code

A burst is a shape the targeting DSL (FR-9) understands: all entities in shape, per-target saves, mixed outcomes. The engine supplies the shape; the pack supplies the consequences.

output — ember-bloom, radius 2
shape burst r2 @ (4,3): grave-shambles · bone-choir · brynn
  per-target save reason → fail 9 fire · half 5 fire · half 5 fire
  // mixed outcomes per target — one declaration, three verdicts

Movement is an action, not a verb

There is no engine move command. A pack declares a move action whose effect is move(<formula>), budgeted by the pack's optional reserved speed formula. It is declared like any action — with a destination — spends the pack's declared slots, and is restricted by conditions through its tags. The engine walks the cheapest legal path (deterministic: fixed neighbor order breaks ties). One declare is one move up to the budget; unspent budget is lost.

pack.json · a move action + its budget
"actions": {
  "stride": {
    "cost": { "slots": { "move": 1 } },
    "tags": ["move"],
    "effect": "move(speed)"      // root statement only · dice-free argument
  }
},
"formulas": {
  "speed": { "expr": "4 + floor(grace / 4)" }   // reserved, optional · evaluated like initiative
}
host code
fight.declare('stride', { to: { x: 3, y: -1 } })
output — brynn strides, speed 4, bramble at (1,0)
move:advanced  brynn (0,0) → (3,-1) · path (1,-1) (2,-1) (3,-1) · cost 3 · remaining 1
move:ended     brynn · arrived @ (3,-1)
  // the bramble detour would cost 4; the plain path wins · the 1 left over is lost

A move that cannot legally reach its destination within budget is rejected declaratively: one declare:rejected, rule E-SPAT-01, and nothing changes — no slot spent, no RNG drawn, no ledger entry. The movement gate runs where the reach gate runs, before cost; a move action targets its actor (no opponent resolution, no reach gate).

rejection kinds — all E-SPAT-01, nothing changes
no-destination   a move action declared without to
blocked          the destination is a blocking terrain cell
occupied         a standing combatant holds the destination — including the mover itself
unreachable      no legal path exists at any cost
out-of-range     a legal path exists, but its cheapest cost exceeds the budget
◈

unreachable means no legal path exists at any cost. out-of-range means a legal path exists, but its cheapest cost exceeds the budget. A reachable destination is never reported unreachable, whatever its cost — a wall detour longer than the budget is out-of-range.

◈

A declare whose to is the mover's own cell is occupied: the mover holds that cell (occupancy rule, below). There is no new kind, no slot is spent, and nothing changes.

Terrain

The pack declares the terrain vocabulary — each kind either costs cost movement points to enter (plain cells cost 1) or blocks and can never be entered. The host places cells per fight, exactly as it places positions, and re-states them on restore. The engine never invents a map.

host code · placement per fight
rt.startCombat({
  allies, enemies,
  positions: { brynn: { x: 0, y: 0 }, 'grave-shambles': { x: -1, y: 0 } },
  terrain: [
    { at: { x: 1, y: 0 }, kind: 'bramble' },
    { at: { x: 2, y: 0 }, kind: 'standing-stone' }
  ]
})
// restore re-states both: Combat.deserialize(snap, pack, { positions, terrain })

startCombat refuses — one E-SPAT-01 aggregate, nothing built — when a kind is unknown, a cell is placed twice, or a combatant starts on a blocking cell. Restore applies the same refusals.

◈

Occupancy (engine rule): a move cannot end on a cell held by a standing combatant — this includes the mover itself. It may pass through standing allies but not standing enemies. Downed combatants (hp ≤ 0) never block.

Leaving reach

Before each step, if the mover's current cell is within reach of a standing opposing combatant and the next cell is not, the engine emits move:leaving-reach — actor = the mover, target = the threatener, payload {at, next}. Opportunity attacks are not engine rules: a pack declares a reaction to that event. Packs without matching reactions never pause.

pack.json · an opportunity reaction
"opportunist": {
  "cost": { "slots": { "reaction": 1 } },
  "trigger": { "on": "move:leaving-reach[target=self]" },
  "effect": "sequence(attack(ac, might), damage(1d8 + might, sharp))",
  "tags": ["reaction"]
}
output — pause → respond → resume
fight.declare('stride', { to: { x: 3, y: -1 } })
move:leaving-reach  brynn ← grave-shambles · at (0,0) next (1,-1)
  // offer grave-shambles.opportunist — the move pauses at (0,0)
  // pendingMove: {actionId: 'stride', to: {x:3,y:-1}, remaining:4,
  // offeredDepartures: [{from:{x:0,y:0},to:{x:1,y:-1},reactorId:'grave-shambles'}]}

fight.respond('grave-shambles.opportunist', 'take', 'brynn')
trigger:fired · attack:rolled · damage:applied
  // queue empty → the move resumes from (0,0) with its remaining budget
move:advanced  brynn (0,0) → (3,-1) · path (1,-1) (2,-1) (3,-1) · cost 3 · remaining 1
move:ended     brynn · arrived @ (3,-1)
  • Offers are per call. A call (declare, respond, use) raises offers only for the events that call emitted — never a replay of the round. Each matching (reactor, event) pair is offered exactly once, and answering an offer never brings it back: one trigger:fired per matching event, at most one trigger:declined per offer.
  • Offers are not filtered by affordability. A threatener whose reaction slot is already spent is still offered, and the move still pauses. The host answers: decline → one trigger:declined; take → one declare:rejected (slot-exhausted, resource reaction, E-ECON-01), nothing spent and nothing else changed. Either answer clears the offer, and the move resumes once none remain.
  • Resume re-checks. Mover downed → move:ended reason downed; a condition now restricts the action's tags → restricted; otherwise re-plan from the current cell with the remaining budget, and no path → blocked. fight.step() while paused forfeits the move (forfeited) before its usual effect.
  • A paused move survives a snapshot. pendingMove rides in the combat snapshot; restore uses combat-over if saved HP defeats a side, otherwise the saved envelope phase. Only legacy omission derives resolved from pendingMove, pendingTrigger or offers; otherwise awaiting-declare, so step() forfeits exactly as it would have without the restart.
  • To take an opportunity reaction when the reactor has several opponents, pass the mover as targetId — respond keeps its existing target resolution.
move events
move:leaving-reach  actor mover · target threatener · { at, next }
move:advanced       { from, to, path, cost, remaining }       // per contiguous segment
move:ended          { reason, at }   // arrived | downed | restricted | blocked | forfeited

AR-05 · Exact departure suppression

New writers always save pendingMove.offeredDepartures, including departures with offers still queued. Resume only after the queue is answered; suppress the complete from/to/reactorId tuple, check a changed edge or new threatener normally, and discard records at move end. The moving actor is the containing combatant; reactorId must name an opponent. Coordinates are integers and tuples unique.

Legacy missing offeredDepartures retains first-step suppression; it cannot promise the stronger correction. This is an approved contract awaiting S04 implementation, not a change to unrelated movement rules.

▲

Cone and line are deferred, not faked (FR-11): they are engine geometry, and the spatial model ships exactly the v1 set — single-target and burst.

◈

Conditions can be spatial too: rooted declares "restricts": ["actions.tagged:move"], so it restricts stride through its move tag — a rooted combatant's fight.declare('stride', { to }) is one declare:rejected (restricted) and nothing changes. No engine special case; it only means anything in packs that opted in (FR-7) — see the conditions surface.
