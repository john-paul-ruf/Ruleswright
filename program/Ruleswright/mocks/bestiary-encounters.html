Bestiary & encounters

Monsters are pack statblocks built from the same character machinery — abilities, class attack tables, saves, actions. There is no second combatant code path (FR-16). And one table engine serves runtime lookups and the compiler alike (FR-15).

A monster is a statblock, and a statblock is a character

bestiary.barrow-wight
{
  "id": "barrow-wight",
  "hp": "hd + vigor × 2",           // same formula DSL (FR-3)
  "ac": "16",                        // descending, pack convention
  "attackTable": [/* same table shape as warden */],
  "saves": { "vigor": 2, "reason": 3 },
  "actions": ["claw", "grave-gaze"],
  "threat": 3                        // feeds encounter budgets
}

A host spawns it with rt.spawnMonster("barrow-wight") and it fights in the same loop, emits the same events, and snapshots the same way.

One table engine

Weighted, ranged, nested. The runtime rolls loot and encounters from it; the compiler generates content from it. Two consumers, zero second implementations (FR-15) — and table rolls ride the seeded RNG, so the same seed replays the same loot (FR-1).

tables.district-scavenge
{
  "id": "district-scavenge",
  "entries": [
    { "weight": 40, "value": "tables.scavenged-supplies" },   // nested
    { "weight": 25, "value": "tables.street-remnants" },
    { "weight": 20, "range": [1, 3], "value": "equipment.med-kits" },
    { "weight": 15, "value": "encounter:hazard" }             // runtime hook
  ]
}

Encounter assembly — deterministic per seed

API illustrative
const enc = rt.assembleEncounter({
  budget: 6,                 // threat points
  party: [brynn, sela],
  table: "encounters.barrowland",
  seed: 42,                  // deterministic per seed (FR-16)
});
output
✓ threat 6 of 6 spent · seed 42
  1× barrow-wight (3) · 2× grave-shambles (1.5)
  heuristic: warden-favored · documented in FR-16 notes
  // hosts may override or bypass assembly entirely
◈

The assembly heuristic is documented, not sacred (FR-16): a pack may replace it or skip it — the engine ships one sensible default and gets out of the way.

✓

Coverage floor (FR-21): both sample packs ship encounter/loot tables and knobs that visibly change output — proven by the theme-knobs surface, consumed here.
