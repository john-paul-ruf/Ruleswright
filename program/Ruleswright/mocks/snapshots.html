Save a whole history. Resume the same decisions.

Approved contract for implementation. New play APIs are not implemented by this Author change. Architect fixes signatures; DB schemas fix portable data. Examples below are the downstream runnable-doc target.

All serializers return detached plain JSON objects. The host calls JSON.stringify and owns storage. No filesystem, database, localStorage or autosave runs in the engine.

Existing independent serializers

serializeCharacter(runtime, character.state); // {kind:'character',snapshotVersion:1,pack,state}
serializeParty(runtime, memberStates);        // {kind:'party',snapshotVersion:1,pack,members}
serializeCombat(fight, { pairsWith: 'party-save-1' });
deserializeCombat(runtime, combatSnapshot, { allies, enemies, positions, terrain });
// The host re-states original profiles/balances and CURRENT positions/terrain.
// Party members are character states, not ids. Character ids remint on restore.

Exact combat envelope anatomy

{ kind: 'combat', snapshotVersion: 1, pack: {id, schemaVersion, contentHash},
  pairsWith, round, turn, order: [combatantId], rng: {a,b,c,d},
  combatants: [{id, hp, maxHp, slotsUsed, conditions: [{id,remaining}],
    position, itemsUsed, poolsSpent, slotsCast, pendingMove}],
  phase, offeredCount, offers: [{actorId,source,id,on}] }
// combatants is an ARRAY. hp is a signed integer. Optional keys omitted, not null.
// slotsUsed = REMAINING per-turn ledger; itemsUsed/poolsSpent/slotsCast = spend.
// pendingMove = {actionId,to:{x,y},remaining,offeredDepartures:[{from,to,reactorId}]}
// rng words: integers 0..4294967295. Legacy optional fields remain accepted.

Character injury is durable

// Added inside character.state (also each party member state):
hp: { current: -2, temp: 3 }
// New writers emit exact signed current HP, including above-derived-max values.
// Legacy absence reconstructs from the existing HP formula and temp = 0.
// Old readers may ignore hp; they cannot preserve the new injury guarantee.
// Conditions keep {id,remaining}; initial combat input maps to {conditionId,duration}.

New aggregate boundary

SaveIncludes / restore inputs
play-sessionStable members + raw combat envelope + original profiles/balances/bindings + current positions/terrain + streams + control + settlement receipts. Restore(pack, snapshot).
adventureDefinition identity + progress/choices + party + active encounter + rewards/receipts + streams + journal + director + narration acknowledgement. Restore(pack, definition, snapshot).

During combat the member envelopes remain the encounter-entry baseline. Fight HP, remaining conditions and spend are authoritative until settlement; detached views project them. Commit all party changes and the receipt together. Never pair a current party with an old fight.

Refuse before construction

Wrong pack/hash/version, duplicate ids, inconsistent sides/order, invalid HP/RNG, insufficient original balances, foreign encounter/receipt or impossible progress phase yields located ErrorCards. No member is half-restored and no ids, entropy or committed journal advances.

Compatibility boundary

Existing snapshotVersion 1 remains. Optional HP and offeredDepartures are additive; old inputs remain readable. New aggregate kinds are separately versioned documents, never passed to the three legacy serializers. Exactly-once receipts apply within one aggregate history; reopening an earlier save is a replay branch. Low-level settlement retains its existing live-object-only idempotence.
