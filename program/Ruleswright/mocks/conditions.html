Conditions & status effects

Conditions are pack data: durations, stacking policy, and what they forbid. Application and removal ride the event stream (FR-7, FR-13), and their teeth come from restricts — a declared rule about what the sufferer may not do (FR-4).

Anatomy

content.conditions — two of the sample pack's several
{
  "id": "sapped",
  "duration": 3,                       // rounds; ticks at endTurn (FR-10)
  "stacking": "refresh",               // pack-declared policy
  "restricts": ["actions.tagged:main"] // no main-slot actions
}

}

Stacking is a per-condition policy

The engine implements the policies generically; each condition declares which one it uses. No condition is special-cased in code.

policy re-application behavior
refreshduration resets to the new value
stackinstances accumulate; each ticks
strongesthighest-magnitude instance wins; weaker re-applies are no-ops

Conditions with teeth

sapped

Restricts actions.tagged:main — the turn arrives, and the main slot has nothing legal to spend on.

silent-tongue

Restricts casting from the Hexer's spoken-word list — the classic "silenced" shape, written as pack data against a pack-declared list tag.

rooted

Restricts move actions — meaningful only in packs that opted into the spatial layer (FR-11); theater-of-mind packs simply never apply it.
