Progression & multi-class

Leveling reads entirely from pack tables — any progression scheme is data. The engine never decides an award: hosts and GMs grant XP, and the engine reports it (FR-6, FR-13).

The leveling table is the pack

HD, class attack tables, save progressions, feat slots, and vancian slots — levels 1–10 in the sample packs. The engine reads them; it has no opinion on their shape.

progression.warden — sample pack, excerpt

Two ways to level — identical validation

direct level-set — character creation
const brynn = rt.createCharacter({
  name: "Brynn",
  race: "hillfolk",
  classes: [{ id: "warden", level: 4 }],  // no XP simulation needed
});
earned — the host awards, the engine reports
rt.awardXp(brynn, 2400);          // host policy, host call
// → event: xp:awarded  why: host.grant
// → event: level:reached  warden 4 (pack thresholds)
// engine emits; it never decides awards (FR-6, FR-13)
✓

Both paths run the same build validator — a level-4 direct set and a level-4 earned set produce byte-identical state (FR-5, FR-14).

Multi-class in v1

A character holds concurrent classes; XP splits per pack policy; each class contributes its own progression tables (FR-6).

a two-class character — API illustrative
const sela = rt.createCharacter({
  name: "Sela",
  race: "hillfolk",
  classes: [
    { id: "warden", level: 3, /* xp share per pack policy */ },
    { id: "hexer",  level: 2 }
  ],
});
// attack, saves: best of each class's table, per pack formula
// vancian slots: each caster class adds its own slot array
caps & restrictions are pack data
"hillfolk": {
  "allowed":  ["warden", "hexer"],      // race/class matrix (FR-6)
  "caps":     { "warden": 8, "hexer": 10 }, // demihuman cap curve
  "multiMax": 2
}
✓

The classic-CRPG curve — class attack tables, five named saves, demihuman level caps — is expressible with zero engine knowledge of "classic" (FR-6, Constraints).

◈

Excluded esoterica (percentile strength, weapon-speed factors) stays addable as pack data later — the tables above don't need to change shape to admit it (Constraints).
