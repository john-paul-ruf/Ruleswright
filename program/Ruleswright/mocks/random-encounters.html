AUTHOR RE-ENTRY · AR-01–06 · FR-24 / FR-14

Play one encounter. Keep the party.

Approved contract for implementation. New play APIs are not implemented by this Author change. Architect fixes signatures; DB schemas fix portable data. Examples below are the downstream runnable-doc target.

Supply a pack, stable member identities and an explicit setup. Inspect choices, send one command and save the entire returned aggregate between calls.

01 · Create → inspect → command → reopen

import { createEncounterSession, restoreEncounterSession } from 'ruleswright/runtime';
import type { Pack, EncounterSessionOptions } from 'ruleswright/schema';

// Caller supplies valid character envelopes and explicit setup; no hidden storage.
export function encounterExample(pack: Pack, options: EncounterSessionOptions) {
  const session = createEncounterSession(pack, options);
  const before = session.view();
  const result = session.dispatch({
    type: 'advance', sessionId: before.sessionId,
    expectedRevision: before.revision
  });
  const bytes = JSON.stringify(session.serialize());
  const reopened = restoreEncounterSession(pack, JSON.parse(bytes));
  return { result, bytes, view: reopened.view(), reopened };
}

03 · Manual decisions

// Each command also carries sessionId and expectedRevision.
{ type: 'declare', actor: { kind: 'member', memberId: 'brynn' },
  actionId: 'stride', options: { to: { x: 2, y: 0 } } }
{ type: 'respond', actor: { kind: 'member', memberId: 'brynn' },
  triggerId, choice: 'decline' }
{ type: 'pass', actor: { kind: 'member', memberId: 'brynn' } }
// Enemy actor: { kind: 'enemy', enemyId }; targetId always uses combatantId.
// 'advance' starts/advances a turn only once; it cannot refresh a started turn.
// 'finalize' commits a terminal encounter; 'next' carries the next setup.
// 'abandon' records spent resources/injury without victory or rewards.

View

{sessionId, revision, phase, members, combat, availableCommands, result, settlement}. Members include memberId, character and combatantId. Combat includes active actor, raw state and pending offers. Every value is detached.

Dispatch result

{ok:true, revision, events, view, receipt?} or {ok:false, revision, errors, events:[], view}. A repeated finalize can return the existing receipt with unchanged revision and no events.

Refused · E-SNAP-01 · expectedRevision: the session has advanced. Display the located ErrorCards and refreshed view. State, entropy and committed journal remain unchanged; do not retry automatically with a new revision.

04 · Settle before the next fight

Finalize stages every member’s HP, remaining conditions, consumables, pools and bindings, then commits one receipt with the party. Next uses that settled party. Save the complete session, never a current party paired with an earlier fight. Older saves reopened independently form replay branches.
