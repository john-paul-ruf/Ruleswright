#### Progress, rolls and receipts

c1/c2 choices/snapshot enforce exact predicates: start visited first; visitedNodeIds equals choiceTrail path including current; resolved/rested unique subsets. Non-encounter resolves on entry; encounter resolves only with victorious settled receipt. `exploration` = current resolved non-success, no active encounter or pending current reward; `encounter` = unresolved current encounter plus matching active session with member baseline; `reward-pending` = current resolved node with pending earned reward and no active encounter. Victory archives `{nodeId,receipt}`, updates members, clears activeEncounter/cursor and stages each authored reward atomically. Defeat takes precedence when both sides down, settles actual spend/injury and terminates. Defeated/abandoned retain previously earned audit records but cannot claim, rest, prepare, equip, use items or choose; no reward staged by these transitions. Completed requires explicit resolved success and all earned rewards claimed, no active encounter. A host success node carrying rewards becomes reward-pending first. Ack remains possible after terminal once S04 implements it. Never infer success from no candidates.

c2 reward staging: `claimId=JSON.stringify([adventureId,nodeId,rewardId])`; record `{claimId,adventureId,nodeId,rewardId,eligibleMemberIds,xpPerMember,stagedRevision,roll,status:'pending'}` in authored reward order. roll is null/no draw without loot, otherwise `{tableId,value,rngBefore,rngAfter,result}` from real rollLoot on a private rewards Rng. Result is `{kind:'item',itemId,qty}` for a resolving string (qty1) or valid `{id,qty}` positive stack; other flavor is `{kind:'no-item'}`. No fabricated dice trace/entry index. Source table leaves and nested refs must satisfy S02 validation. Failed table outcome rolls back settlement/node transition, every stream, journal and all claims. Reopen validates exact value normalization and replays on a detached RNG to check endpoints, never a live reroll; stored rolls chain in staged order to current rng.rewards. Add c2 fixtures and assertions in rewards.test.ts plus the generated adventure journey before c3 depends on this producer.

c3 claimed records retain those fields/status:'claimed' and add receipt `{receiptId,adventureId,definitionHash,claimId,nodeId,rewardId,revision,eligibleMemberIds,recipientMemberId,xpPerMember,grants,beforeMembersHash,afterMembersHash}`. receiptId JSON.stringify([adventureId,claimId,'reward']); recipient null only for no loot; grants empty or exactly one `{memberId,itemId,qty}` matching saved normalized roll. H of ordered pre/post member arrays; after hash uses the **preserved final state**, never intermediate awardXp state. One reward cannot clear another; matching idempotent retry returns its receipt, altered subject/recipient or stale revision refuses. Historical hashes are consistency evidence, not protection against a coherent rewrite of an entire save.
