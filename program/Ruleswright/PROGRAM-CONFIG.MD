## Architecture

- **Pattern:** layered library. `schema` and `core` are sibling leaves importing nothing internal. `runtime` and `compiler` each depend on both. `runtime` must **never** import `compiler` (CI-enforced, string check on the runtime-only bundle). No cross-surface re-exports.
- **Dependency flow:** `runtime → {schema, core}`, `compiler → {schema, core}`; `compiler`'s final pipeline stage *is* `schema.validatePack` (dogfooding without importing runtime).
- **DSL:** string mini-languages, parsed once at load into validated ASTs; closed function registry; no `eval`/`new Function`/dynamic imports ever.
- **RNG:** sfc32 (four uint32 words), cyrb128-class seed hashing, injectable, state export/import.
- **Validator:** hand-rolled, pure, all-at-once, never partial; emits the one `ErrorCard` shape everywhere. The compiler consumes it directly (never the runtime's copy). *(v1-shell: split into `validate/` directory — one module per pass/section; same public surface.)*
- **Entry points:** `src/index.ts` (dumb re-export) + three subpath entries.

## Conventions

- **Naming:** files kebab-case; types PascalCase; exported functions verbs; ids kebab (`^[a-z][a-z0-9-]*$`).
- **Errors:** one shape everywhere — `ErrorCard { severity, artifactId, jsonPath, rule, message, hint? }`. Load validation returns `ErrorCard[]` (empty = valid). Illegal runtime operations throw an aggregate carrying ErrorCards. Never swallow; never catch-and-rethrow without adding context.
- **No I/O** anywhere in `src/`: no fs, no fetch, no timers, no `Date.now`, no `Math.random` (lint-enforced).
- **State:** plain serializable JSON only — no class instances, closures, or hidden state inside character/party/combat state.
- **Determinism:** no ambient entropy anywhere; provenance is exactly `{theme, seed, knobs}`; canonical JSON (sorted keys) for hashing and generation output.
- **Docs:** README examples must be executed by a test (NFR-DX).
- *(Promoted 2025-09-27, grid-combat final pass — evidence axis: 2 program cycles, 3 in-cycle instances; see ARCHIVIST-LOG.md.)* **Pin-lease ownership:** any test that pins a count/shape defined in another suite's artifacts (docs-run's README ```ts block-count pin, registry.test.ts's RULE_IDS order/count pin, coverage-floor's floor arithmetic) must name its re-key owner and checkpoint in the plan, whenever any suite in the same feature lands changes to the pinned artifact. Unowned pins discovered at a quiet boundary are planning defects, not worker discoveries.
- *(Promoted 2025-09-27, grid-combat final pass — evidence axis: 2 program cycles, 4 in-cycle instances; see ARCHIVIST-LOG.md.)* **Factual-premise verification at planning time:** every envelope premise that asserts a mechanical fact about committed artifacts (mock-vs-prompt anatomy equivalence, cross-suite counts, symbol existence, baseline arithmetic) is checked against the artifact before session dispatch, by a planning-completeness review or a mechanical probe — never deferred to checkpoint 0 as a discovery. A disproved premise found in a session is returned for a bounded prompt correction (checkpoint-0 rechecks verify, they do not originate premises).
- *(Promoted 2025-09-27, grid-combat final pass — evidence axis: 3 program cycles (v1-core OWNER-01-LINT `c5fbb94`, loot-inventory FORMAT-RECONCILE `8b802b7`, grid-combat `0ab3622`); see ARCHIVIST-LOG.md.)* **Whole-repo fast gates at role-scoped receives:** typecheck/lint/format:check go red at receives that run only lease-scoped or single-role verification sets. Every role-scoped receive runs the whole-repo fast gates before accepting; a red gate is cleared by a format-only owner correction under standing authority, counted as an owner correction, and recorded (the CI format leg stays green on every land). DB/Author workers stay within their role-scoped evidence set; the whole-repo gate remains Orchestrator's receive check.

## Custom Rules

1. **Contracts are frozen for Coder:** `src/schema/contracts/**` is DB-owned. Schema changes are Author re-entry (schema-change class), never a lease adjustment. *(Realized so far: DB v1.2 added `content.classes.<id>.actions`; DB v1.3 added the optional top-level `spatial` + registered `E-SPAT-01`; `RULE_IDS` re-keyed 14→15 additively — each landed by a sanctioned DB author session, never by a lease adjustment.)*
2. **Reserved formula ids (v1 convention, validator-enforced):** every pack's `formulas` map must define `hp` and `ac`; `initiative` optional (engine fallback: plain d20). Engine resolves derived stats only through these reserved ids — never hardcoded math.
3. **One table engine:** `src/core/tables.ts`. The compiler has no private second implementation (FR-15). Runtime loot rolls through the same engine (loot-inventory).
4. **No magic subsystem:** spells are actions + metadata; casting rides the normal action pipeline (FR-9). *(grid-combat finding, recorded not relitigated: combat `declare()` resolves actions only from `pack.actions` — a "spells as combat actions" bridge would be an engine design event (Author/DB re-entry class), not a convention change here.)*
5. **Cross-runtime determinism proof is CI's job** (Node 18/20/22 + browser mode); local proof is integer-arithmetic determinism + state export/import tests. *(The browser leg is an honest documented v1.1 follow-up — README + ci.yml say so.)*
6. **New sample content is coined** (expression policy Q7/Q8): no SRD names/phrasing; "d20" only as generic body-text term.
